### 남은 확인 작업 (Supabase 프로젝트 생성 후)
1. 마이그레이션 실행 → 대표 지정 → 로그인
2. 계정 관리에서 4가지 역할 계정 생성 → 각 계정으로 로그인해 보이는 지점·메뉴 확인
3. 아이디 방식 계정 생성이 되는지 확인 (내부 도메인 허용 여부)
4. 사용 중지 → 해당 계정 즉시 차단 확인
5. 변경 이력에 위 작업이 수행자와 함께 남는지 확인

### 알려진 제한
- 비밀번호 초기화(Auth 영역)는 감사로그 테이블에 남지 않음 (Supabase Auth 자체 로그에는 남음).
- 계정 생성 시 프로필 갱신이 실패하면 방금 만든 Auth 계정을 삭제(보상 처리)함.
- 지점 정보 수정 화면은 2단계.

## 3단계 보완 — 실시간 원가율 · 냉장고 재고 비율 (2026-10-13)
대표 요청: 거래처 미수(외상 매입)가 쌓이는 동안 매출 대비 원재료비가 몇 %인지 실시간으로 보기. 냉장고 보관 재고는 5~10%로 **대표만** 지점별 설정.
계산: 원가율 = (이번 달 식재료 매입[외상 + 바로 결제] − 매입 × 냉장고 재고 %) ÷ 이번 달 실매출.
월말 재고(전월 말 + 이달 말)를 직접 센 달은 비율 대신 실제 매출원가. 3단계의 '재고 없으면 매입액 = 원가'는 이 계산으로 바뀜 (손익 화면도 같은 숫자).

## 3단계 보완 — 거래명세표 사진 AI 읽기 (2026-10-13)
대표 결정: 거래처를 고르고 거래명세표를 찍어 올리면 AI가 품목·수량·단가·금액·잔액을 읽음 · **올린 사람이 사진과 비교해 확인**하고 못 읽은 칸은 직접 적음 · 사진은 보관.

모델: `gemini-3.8-flash` → 한도 초과·혼잡이면 `gemini-3.6-flash`. SDK(@google/genai)는 수십 MB 라 쓰지 않고 REST 직접 호출(묶음 약 1.6MB). 마이그레이션 0700 주석의 'Claude Opus 5.5'는 당시 기록.
구조: 브라우저 → 사진 2장(AI용 선명한 것은 바로 전송, 보관용은 작게 줄여 Storage 비공개 버킷) → Supabase Edge Function `read-statement`(최대 150초, Netlify 10초 제한 회피) → 확인 화면 → `confirm_purchase_statement`(DB 함수)로 식재료 지출+품목 줄(+부가세 줄) 생성.
권한: 대표·소속 본사/지점 관리자만 올리기·확정. 지점 관리자는 지출 표는 여전히 못 봄(확정 금액은 거래명세표 기록에서 확인). 비용 보호: 한 장 3번, 지점당 하루 50장.
